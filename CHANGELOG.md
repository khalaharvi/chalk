## 0.6.0 (2026-10-04)

### Features

- Every loop that makes no progress gets a verdict (`first`, `deja_vu`,
  `repeat`, `no_change`, `improving` and others), recorded in shadow mode
  by default (`CHALK_FP_RULES`). The report card shows whether stopping
  early would have paid.
- JUnit XML test reports, through `CHALK_TEST_REPORT`, name the failing
  tests for the verdicts.
- The database moves to Postgres 17 with pgvector. `chalk db upgrade`
  moves an existing Postgres 16 database and rolls back on failure.
- `CHALK_MAX_PARALLEL=auto` sizes `chalk fleet` to Docker's CPUs and memory.

### Fixes

- The first fleet launch on a fresh machine no longer fails to start the
  database.
- Agent costs are rounded to four places.

## 0.5.0 (2026-10-04)

### Features

- Repositories hosted on GitHub are supported: pull requests through `gh`
  and gates in GitHub Actions, next to GitLab.
- Chalk runs under bash 5.3 on the host and re-executes itself under a
  newer bash when started from an older one. Sandbox images need bash 5.2.
- A run's services start in parallel.

### Fixes

- A detached run shows as running as soon as it starts.
- The final review is told which commands it may run.
- Each call records the model that actually ran it.
- The report card and run summaries agree.

### Documentation

- How to give `chalk fleet` access to Jira.
- The bash conventions, in `docs/bash-style.md`.
